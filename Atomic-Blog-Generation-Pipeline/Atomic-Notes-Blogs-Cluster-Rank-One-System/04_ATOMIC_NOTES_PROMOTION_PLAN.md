# Phase 0: Entity and Technical Foundation

Before starting the 15 campaigns:

## 0. Launch Gate (blocks every "download" call to action)

Atomic Notes needs a Google account, and while the Google OAuth consent screen is in testing, Google lets only approved test users sign in. Traffic that can't sign in is wasted, and it reads as a broken product.

Before Week 1:

• publish the OAuth consent screen (home page, privacy policy, and terms on atomic-notes.devbehindyou.com, devbehindyou.com verified in Google Search Console, verification approved)
• confirm a brand-new Google account can install the latest APK and sign in
• until then, point CTAs at the GitHub repository ("read the code", "watch releases") or the support page, never at "download and start"

## Status checked on October 7, 2026

• atomic-notes.devbehindyou.com is live over HTTPS. The old atomic-notes-community.vercel.app host 308-redirects every path.
• Canonicals, the sitemap, robots.txt, the RSS feed and llms.txt use the new domain only.
• Status on October 9, 2026: 7 Main Blogs are live on the site (L1, P1, S1, L3, P5, L5, P2; Community PRs #14 and #15), L2, S2, L4, P4 and P3 went live through Community PR #16, and S3, S4 and S5 are in Community PR #17, so all 15 Main Blogs are written. None of the 27 older drafts is on Medium or anywhere else as far as we know, so no draft is a live duplicate. Draft slugs for unpublished pages can still change (see `keyword-registry.json`).
• The existing drafts run 1,000 to 1,500 words. Main Blogs should grow toward the depth their intent needs (often 1,800 to 3,500 words) when they are re-keyworded.

# Linking Architecture

## Support to Main

Every Support Blog should have at least one clear contextual link to its assigned Main Blog.

Examples of natural anchor styles:

• branded: `Atomic Notes by DevBehindYou`  
• descriptive: `guide to privacy red flags in notes apps`  
• partial-match: `local-first notes app guide`  
• question-based: `what end-to-end encryption actually protects`  
• naked URL when it is natural

Do not repeat one exact-match anchor across dozens of external pages.

## Support to Support

Use sparingly.

Good:

`P5-S2 → P5-S1` when a metadata article naturally references zero telemetry.

Bad:

Every Support Blog linking to every other Support Blog.

## Main to Main

Use the cross-link graph in `02_ATOMIC_NOTES_MAIN_AND_SUPPORT_TOPIC_MAP.md`.

Internal links should help a reader move from:

definition → comparison → technical depth → product decision.

# GEO / AI Answer Engine Plan

For every Main Blog:

## Entity Statements

Use plain factual sentences that can stand alone.

Example pattern:

**Atomic Notes by DevBehindYou is a source-available, local-first notes app for Android that saves every note on the phone first and syncs it to the user's own Google Drive.**

Only publish a statement if it is currently verified.

## Quotable Answer Blocks

For common questions, give a concise answer first, then detail.

Example:

### Is local-first the same as offline mode?

**No.** Offline mode can simply be a temporary cache. Local-first software treats local data as a primary part of the architecture and can continue meaningful work without depending on a network request.

## Tables

Use factual tables for:

• encryption model  
• storage model  
• offline behavior  
• account requirements  
• source license (open source, source-available, or closed)  
• AI features  
• exportability  
• sync model

## Sources

Prefer:

1. official documentation
2. official GitHub repositories/releases
3. official store listings
4. standards/security documentation
5. reputable independent sources
6. Reddit/community sources for sentiment only

The social layer is not just link distribution.

Its job is to create:

• branded search demand  
• discussions around the target concepts

• repeated entity association  
• content ideas from replies

# Reddit Plan

Reddit deserves separate handling.

For every planned Reddit post:

1. find a genuinely relevant subreddit
2. read current subreddit rules
3. search for recent discussions on the topic
4. write a self-contained useful post
5. disclose that you build Atomic Notes when mentioning it
6. ask for feedback rather than pretending to be an unrelated user
7. link only if allowed

A no-link Reddit discussion can still be valuable for research, brand discovery, and future content improvement.
